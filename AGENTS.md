Весь этот чат — одна задача.

В начале новой задачи проверь актуальность кода, используя git, в каждой папке проекта, чтобы избежать работы над неактуальным кодом.

До изменения файлов проекта создай отдельный Git worktree и уникальную ветку задачи для каждого репозитория, который будешь изменять или использовать для запуска. Незакомиченные изменения переносить в worktree не нужно. Если удалённого репозитория нет — используй текущий локальный коммит.

При последующих сообщениях продолжай работу в тех же worktree — не создавай новые.

### Порты

Используй отдельные свободные порты (проверь какие заняты) и локальные данные/БД под задачу. При наличии существующей локальной dev-БД используй её отдельную копию, а не пустую БД.

### Когда закончил

Запусти приложение локально, чтобы я мог проверить твою работу, но только если это разумно — если ты поправил тесты, например, то я их не увижу в интерфейсе и не проверю — запускать не надо.

Веб приложение: backend (если есть) и фронтенд (если есть).
Также создай отдельный Cloudflare Tunnel с помощью cloudflared (если его нет на устройстве - предложи установить). Если в приложении есть авторизация, то с адресом dev-<task>.vzl0m.com (OAuth — через production OAuth Proxy, данные и сессии — локальные для задачи), если нет - без кастомного домена. При сетевой блокировке Cloudflare сообщи пользователю об этом (он знает как починить), не пытайся сам починить. Если есть backend, обязательно проверь связь с фронтендом - сделай чтобы всё работало.
Дай просто ссылки (localhost и cloudflare), я сам открою.

Десктопное приложение: у приложения может быть singleton токен, осторожно.

ТГ-бот: при конфликте использования токена останови запущенный тобой экземпляр.

Если это не Git-репозиторий — предложи инициализировать его.
Публикацию на GitHub через gh предложи отдельно.

### Публикация и уборка

Когда я скажу заливать, нужно сделать commit, push, merge... короче чтобы в исходной ветке всё это было.

После успешной публикации нужно удалить больше не нужные созданные worktree, слитые ветки и временные данные/БД и т.д.
